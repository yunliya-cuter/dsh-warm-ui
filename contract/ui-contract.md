# dsh-warm-ui 界面契约（人读版）

机器可读的那份是 `contract/ui-contract.json`；这里说清"每个状态应该长什么样"，
以及**为什么**是那样。改设计先改这两份，再改代码。

## 1. 注入节点的规矩（三条，全部由 `tools/check.mjs` 守）

1. **样式表必须自己打 `data-plugin`。** 模块加载器只在工厂返回那一刻认领还没打标的
   `<style>`，热重载也只删 `style[data-plugin=<包名>]`。不打标的表既会被后加载的插件
   错认成自己的、又永远删不掉 —— 每加热更一次 `<head>` 里就多一份完整旧表。
   症状：旧表把玻璃滤镜 svg 撑出 255px 高，页面能往下滚，"壁纸跑到页面下面"。
   **实现只有一份**：`preview/shared/lib/client.js` 的 `createStyleInstaller(包名)`
   （见第 5 节）。各包只调用它，不再自己抄一遍。
2. **每个注入节点必须有归属标记。** 属性 `data-dsh-warm-owner`，值 `包名:节点名`；
   语义标记（CSS/探针用）由每个包的登记表 `NODE_OWNERS` 一行给出，字符串只写一遍。
3. **页面外层的节点只能经挂载助手入文档**（`mountDetached` / `mountLayer` /
   `installStyleSheet`）：贴标 → 钉死定位 → 清扫上一代 → append。裸 append 会被静态检查拦下。

### 登记表（一类节点一行）

| 包 | 节点名 | 语义标记 | 定位 | 说明 |
| --- | --- | --- | --- | --- |
| dsh-warm-ui | `glassSvg` | `data-wta-glass-svg` | 内联 `fixed`，0×0 | 玻璃滤镜定义，只有 `<defs>`，不需要可见区域 |
| dsh-warm-ui | `optimizerPop` | `data-dsh-warm-optimizer-pop` | 内联 `fixed` | 档位/权限下拉，left/top 由 `place()` 按需写 |
| dsh-warm-ui | `guardNote` | `data-dsh-warm-guard-note` | 内联 `fixed`（左下角） | **按需**：只在文档真的溢出时出现，出现即代表某条不变量破了 |
| dsh-warm-ui | `collapseChip` | `data-dsh-warm-collapse` | 无（就在工具行里） | 「优化」胶囊，本来就该参与排版 |
| dsh-warm-wallpaper | `layer` | `data-dsh-warm-wallpaper-layer` | 内联 `fixed` 铺满，`z-index:-1` | 壁纸画布 |

**为什么定位要写内联**：`width="0" height="0"` 这类表现属性在 CSS 里是最低一档，
任何样式规则都能盖掉它（包括热更残留的旧表）。一旦被盖出尺寸，覆盖层就变成文档末尾
一块看不见的空白 —— 页面能滚下去、壁纸露在下面。内联永远赢样式表。

## 2. 工具行三态（`body[data-dsh-warm-dpo]`）

断点**只在第三方插件里**，我们不写媒体查询（写两份迟早对不上）。我们读它渲染出来的
DOM，把结果写到 body 属性上：

| 状态 | 条件 | 期望外观 |
| --- | --- | --- |
| `chip` | 插件渲染出滑杆（宽屏） | 我们的「优化」胶囊在（24px 高），插件两根滑杆都藏起来 |
| `native` | 插件渲染出 `[data-dpo="tier-collapsed"]`（窄屏） | 我们的胶囊不在，权限滑杆藏起来，档位用它自己的窄屏形态 |
| `fallback` | 认不出插件 DOM | 一切原样，我们的胶囊不在（绝不留下点不动的空壳） |

行高 24px 只在 `chip` 态断言（那是我们定的形态）。

### 工具行里只该有**一颗**「优化」胶囊（2026-09-24 用户报重复）

清扫按**类名**（`.wti-chip`），不是只按归属标记 `data-dsh-warm-collapse`。
理由是标记后来才加：页面里可能还留着更早一代插件造出来的同类节点，它**没有**那个属性，
只按属性扫永远扫不到 —— 于是新胶囊插进去之后两颗一模一样地并排待着（用户截图报的就是
这个；成因已复现：往 `.dpo-controls` 里塞一颗无标记的同类节点，再触发一次热重载，
计数就从 1 变 2，且此后一直是 2）。

同时加**换代守卫**（`chipGeneration`）：只有最新一代实例允许写工具行，被换代的那一代
即使还有排队中的 rAF / 观察器回调也立刻停手 —— 否则两个活着的实例会"你删我的、我塞回
我的"打成每帧互相打架。两条合起来的保证是"同类节点恒为一"，真机断言里数 `.wti-chip`。

## 3. 输入框宽度：跟着 DSH 自己的偏好走

卡片宽度**不是我们定的**。DSH 的算法（`dsh-client-ui-conversation/lib/client.js`）：

```
--dsh-chat-user-width   = clamp(偏好, 640, 列宽 - 176)      # 有偏好时
                        = clamp(列宽 * 0.64, 680, 920)      # 没有偏好时
--dsh-composer-card-max-width = --dsh-chat-user-width + 32
```

- 偏好键：`localStorage["dsh.conversation.contentWidth"]`（拖动会话宽度手柄才会写）。
- 没有偏好时上限就是 `920 + 32 = 952px`，与会话正文列同宽（正文列也用它）。
- **实测**（2026-09-19，真 Firefox）：
  - 无偏好、窗口 1752 → 卡片 952px；
  - 偏好 1200、窗口 1752（列宽 1472）→ 卡片 1232px = 1200 + 32；
  - 同一份偏好 1200、窗口 1200（列宽 920）→ 卡片 776px = (920 − 176) + 32。

也就是说：**"进了 plan 模式输入框变宽"= 同一份偏好被更宽的可用列放了出来**，
不是插件干的（插件不写这两个变量、也没有任何一条宽度规则）。
要回到默认宽度：把宽度手柄拖回去，或者在控制台执行

```js
localStorage.removeItem("dsh.conversation.contentWidth"); location.reload();
```

## 4. 全局不变量（真机断言）

| 不变量 | 期望 | 为什么 |
| --- | --- | --- |
| 文档溢出 | 0px | 一旦能滚，壁纸就会露在页面下面 |
| 每张样式表份数 | 1 | 热更残留会互相抢规则 |
| 无主样式表（没 `data-plugin`） | 0 | 那些表热重载删不掉 |
| 每个登记节点份数 | 1（按需节点为 0） | 两代节点同时存在会导致"守卫对着上一代读问题" |
| `missingCssVars` | 空 | 未定义又没兜底的变量会让整条声明被复位 |
| `layoutGuard` | 无 | 它一出现就说明上面某条破了 |

## 5. 共享代码与依赖方向（`dsh-warm-shared`）

被两个以上包用到的**平台约定**放在 `preview/shared`（包名 `dsh-warm-shared`），不在各包抄一遍：

| 共享的东西 | 为什么必须是同一份 |
| --- | --- |
| `createStyleInstaller(包名)` | 第 1 节的三件套；抄错一次就是"样式表删不掉/被错认"，两个线上 bug 都出在这里 |
| `cssPropertyName` | camelCase → kebab 的命名规则：内联样式与生成的 CSS 必须用同一条规则，否则表里和 DOM 里对不上 |

依赖方向**单向**：`dsh-warm-ui` / `dsh-warm-wallpaper` → `dsh-warm-shared`（不允许反向、不允许环）。
声明一条依赖要**三处同时改**，`tools/check.mjs` 的「共享依赖」一条逐条核对：

1. 代码：工厂体里 `require("dsh-warm-shared")`；
2. 本包 `package.json`：`dsh.client.external: ["dsh-warm-shared"]`（宿主据此把依赖行排在本包之前）；
3. 契约：`packages.<包>.requires: ["dsh-warm-shared"]`。

同一条检查还会拦下"依赖方又自己实现一遍注入三件套"（代码里再出现 `dataset.plugin =`）。

**不放进共享包的东西**：`NODE_OWNERS` 登记表、`pinOverlay`/`pinLayer`、`sweepOwned`/`sweepLayers`、
`checkCssVars` —— 它们看着像，但每个包的清扫副作用不同（壁纸要顺带清渲染器缓存），
硬抽一层只会多一层间接。共用的**约定**写在契约里，代码保持各包自洽。

## 6. 玻璃不做动效（2026-09-24 删掉「流动层」）

液态玻璃只有三样，全是**静止**的：折射、边缘光、表面反射。
**玻璃上没有任何随时间变化的位移** —— 契约里这句话的 machine 版是 `glass.motion.state = "none"`。

曾经有过一层：`GLASS_WARP.ripple`（`feTurbulence` 噪声 + 一次额外位移）由 20fps 定时器
驱动 `baseFrequency` / `scale` 缓慢摆动，让玻璃底下的内容持续游动。当时的用户要求是
"能看清字，但要明显看得出在动"。2026-09-24 用户改主意了：

> 「消除输入框边缘波纹动效」「波纹：直接去掉，保持输入框原有静态外观（圆角、描边、阴影、间距）不变」
> 「不要用另一套动效替代波纹（不要换成阴影呼吸、渐变动画、边框流光等）」

于是整层删除：`GLASS_WARP` 配方表、`warpAt` / `warpFilterNodes` / `glassWarpOf`、
驱动定时器与驱动登记表、`GLASS_MATERIAL.warp/warpAmp`、`GLASS_CALM.scale.warpAmp`、
引擎表的 `warp` 列、`EXTRA_DEFAULTS.glassWarp`、`buildGlassMap` 里的边缘遮罩、
契约的 `glass.warp`、`tools/probes/glass-warp.js`、静态检查里的「动效门槛」。
**删的是实现，不是"看起来不动"**：滤镜图里不再有噪声原语，body 上不再有
`data-wta-glasswarp`，`EXTRA_DEFAULTS` 里不再有 `glassWarp`。
（三道门 —— 系统设置 / 开关 / 引擎列 —— 随这一层一起删：没有持续动效就不需要门。）

守这件事的两处：`tools/check.mjs` 的「玻璃无动效」（静态：代码里不许再有配方/原语/开关，
契约改了它才放行）、真机断言 `probes/contract.js` 第 ⑨ 节（运行时：滤镜里 0 个噪声原语、
body 上没有那个开关标记）。

**注意：删掉这一层并不等于"输入框不闪了"。** 用户接着报的「经常闪烁」是另一个原因 ——
同时有好几代**没被卸载**的旧实例在写同一个输入框（见第 7 节）。玻璃不动了，但"谁在画"
没定下来，照样闪。

### 为什么删：实测那张卡片（不是凭感觉）

同一张输入卡片（1752×830，Chromium/Edge），两张相隔约 4.5 秒的截图做差分
（平均绝对差；区域 = 卡片，x 535..1487）：

| 状态 | 卡片上沿带（y 388..418） | 卡片整块（y 388..502） |
| --- | --- | --- |
| 现状（壁纸在 + 流动层在） | **5.73**（26.3% 像素差 >8） | — |
| 把流动层驱动**冻住**（拦掉 `baseFrequency`/`scale` 的后续写入；壁纸照旧） | 5.43（21.7%） | 7.88 |
| 把**壁纸那层**藏掉（流动层照旧） | **0.233**（0.07%） | 1.545 |

读法：卡片边缘的"动"绝大部分来自**会动的壁纸透过玻璃**（5.43 / 5.73 那条），玻璃自身
那点动是 0.23 这一档。所以删掉流动层之后，输入框边缘**仍会**看到壁纸在动 —— 那是壁纸
自己的动效（`dsh-warm-wallpaper`），不是玻璃的。要连它一起静止，只有"关掉壁纸"或
"让玻璃不再采样背景"两条路，两条都会改变现在的观感，**没有替用户决定**。

### 引擎能力（静止折射仍然靠这张表）

| 滤镜挂在哪 | Chromium（无头 Edge） | Firefox 154（无头） |
| --- | --- | --- |
| `backdrop-filter: url(#…)` | ✓ `feOffset` +12.00px、`feImage` −12.00px、噪声图案打乱 | ✗ **三种配方全部 0px** |
| `filter: url(#…)`（元素自身） | ✓ | ✓（`feImage` 要给 `xlink:href`，只写 `href` 等于没有图源） |

即：Gecko **完全不认** backdrop 里的 SVG 滤镜 —— Firefox 上的玻璃只有 blur/tint，
折射与边缘光都不生效（`GLASS_BACKDROP_ENGINES[].svgFilter` 为此写 false）。
量法：`tools/probes/engine-glass.js`（同一张竖条纹，压了玻璃的那块相对没压的那块位移多少）。
Firefox 唯一的补法是给会话内容挂元素级滤镜，实测每帧多花 ≥17ms
（`tools/probes/glass-cost.js`：中位帧 33ms → 50ms），所以不做。

## 7. 插件实例的生死（换代守卫 + 出错自我卸载）

> 这一节是回应 2026-09-24 的另一半问题：删掉流动层之后，用户仍报「输入框**经常**闪烁」。

闪烁的成因不在玻璃的画法，而在**有几个实例在画**。热重载换掉的是模块实例：旧实例的
`pointermove` 监听、`rAF`、`MutationObserver` 都还在跑，而它的代码已经过期。用户那一次
现场是三份**半删状态**的 `rev` 同时活着（删流动层的过程中存过三次"语法没错、运行会抛"的
中间态），每一份都在 `onPointerMove → … → sync → dress` 上抛 `GLASS_WARP is not defined`
之类的错 —— 工具行那次是几代互相删插同一颗「优化」胶囊。修法是两条：

1. **同时只允许一代写页面。** 换代计数器挂在 `window` 上
   （`GENERATION_KEYS`：`__dshWarmGenGlass` / `__dshWarmGenChip`），
   `generationOf` / `beginGeneration` / `endGeneration` 是唯一定义处。玻璃的 `sync()`
   与工具行胶囊的 `step()` **第一句**就是换代守卫：号码不是最新的，立刻停手。
   **不许再把号码记在模块作用域的变量里** —— 新模块从 0 开始数，两代互不认识，
   守卫等于没有（原来那个 `chipGeneration` 就是这么失效的）。
2. **出事的那一代自我卸载。** 玻璃的 `sync()` 是 pointermove 热路径，出错就
   `remove()`（幂等，`dead` 标记）+ `reportGlassFailure()`（**只报一次**），页面回到
   "没有玻璃但能用"。`mountExtras()` 同理：先定义好 `dispose`，每一步装上来的东西都
   登记成可撤的，`paintExtraFlags` / `mountGlass` / 第一次 `sync` 任一步抛出去都按逆序
   撤干净 —— 半成品留下的监听，下一次挂载就变成两代同时写页面。
3. **有出口可问。** `window.__dshWarmExtra.glass` 报 `{ alive, generation }`（出错时附
   `error`）。没有出口的时候，"玻璃悄悄死了、页面只是看起来还行"只能靠肉眼看出来。

实测（`tools/probes/glass-zombie.js`：假 loader + 假 ctx 连挂两代，`effect` 不给卸载，
再在输入卡片上打 120 发指针风暴）：

| 状态 | 合计 DOM 变更 | 风暴段 | 静置段 | 继续静置 | 其中 `.wti-chip` 删插 |
| --- | --- | --- | --- | --- | --- |
| 改前 | 2233 | 未分段 | 未分段 | 未分段 | 868 |
| 只加换代守卫 | 79 | 未分段 | 未分段 | 未分段 | 4 |
| 全套改完 | 71 | 71 | **0** | **0** | 4 |
| 单实例基线（对照） | 5 | 5 | 0 | 0 | 0 |

「分段」是探针后加的：前三行是同一个窗口（120 发指针风暴 + 1.2s 静置 + 1.2s 继续静置）
的合计，改前那两行没有分开数。读法是**静置段**：闪烁是"每帧都在写"，改完后静置段与
继续静置段都是 0，剩下 71 次全落在挂载那一瞬（两次换代换手 + 新一代补一次样式）。

用户侧现场的数字是 5 秒 1284 次 DOM 变更；同一个探测器在**全新加载**的页面上是 0 次。
把 `document.elementFromPoint` 换成必抛之后：

| | 未捕获错误 | `console.error` | 可观测出口 |
| --- | --- | --- | --- |
| 改前 | 59 | 0 | 不存在 |
| 改完 | **0** | **恰好 1 条**（文案带「已自我卸载」） | `{ alive: false, generation: 3, error: … }` |

另外 `tools/check.mjs` 第 11 项扩成了一张**已删标识符表**（15 个名字：`GLASS_WARP`、
`warpAt`、`warpFilterNodes`、`glassWarpOf`、`feTurbulence`、`data-wta-glasswarp` …）：
半删状态过得了 `node --check`，只有这张表拦得住。

**边界**：代码拦不住"守卫上线之前就活着的实例" —— 用户那三份僵尸实例只能靠**硬刷新**
清掉；换代码时也要保持"每一次存盘都是自洽状态"（先加新东西 → 再切调用点 → 最后删旧的）。

## 8. 底部曲率与文字可读性（2026-09-25）

用户报「输入框玻璃底部曲率过大」，随后追加「我感觉曲率还是太大了」。落进代码里，
「曲率」= **底边折射带里的位移幅度**（玻璃底下的背景被掰弯多少），它有两个旋钮：

| 旋钮 | 管什么 | 基准 | 输入框卡片槽位（`GLASS_SLOT_VARIANTS.composer`） |
| --- | --- | --- | --- |
| `slope` | 弯得**多快**：位移随深度的增长率（= 边缘局部放大倍数 − 1 的封顶） | 1.5 | ×0.6 → 0.9 |
| `dispGain` | 弯的**总量**：位移场整体倍数（边缘带 + 整片透镜一起乘） | 1 | ×0.5 → 0.5 |

只作用于输入框卡片：槽位表里任务面板那一行 `variant` 为空 = 用基准材质（不跟着变）。

改一个变量就量一次（`tools/probes/curvature.js`，读的是**渲染真正用的那张位移图**）：

| 阶段 | 底边带峰值位移 | 带内每像素衰减 | 全局 maxd | 透镜尾巴 | 底边弧剖面峰值 | 内阴影 / 圆角 / 底色 |
| --- | --- | --- | --- | --- | --- | --- |
| 基准（`slope 1.5` / `dispGain 1`） | 15.97px | 2.02px/px | 18.42px | 6.33px | 0.529 | 5 层 / 22px / `.30` |
| 只折 `slope ×0.6` | 10.64px | 1.54px/px | 14.04px | 6.36px | 0.537 | 5 层 / 22px / `.30` |

读法：折射（前两列）降了 2/3，而**弧那一列与「内阴影 / 圆角 / 底色」一字未动** ——
这正是「不许拿曲率换可读性」的意思：降的是掰弯的幅度，不是那条下缘弧度本身。
`thickness` 也试过（70 → 42）：峰值只从 18.42px 掉到 16.76px（−9%），因为剖面被
`slope` 夹住的那一段不随厚度变 —— 那一版撤销，厚度回基准。

**文字那一半**：输入框 DOM 里的字**永远不被滤波**（实测可编辑区 `filter` 与
`backdrop-filter` 都是 `none`，字色 `rgb(223,225,230)`），所以"字清不清楚"只取决于
它背后的背景对比。四态的实测口径见契约 `glass.legibility`：

## 9. 悬停判定与「窗口失焦」（2026-09-25）

用户报「鼠标停在输入框上打字，输入框由模糊态回退成透明态，鼠标一动就恢复」。

悬停**不靠 `:hover`**（DSH 按键时会重建卡片节点，节点一换 `:hover` 当场失效），而是
**记住指针坐标 + `document.elementFromPoint` 命中测试**。判定成悬停时插件写两个内联状态量
（底色 `.62` / 模糊 `blur 4px` / 表面反射 `0.3`），否则是常态（`.30` / `blur 0` / `1`）。

根因：窗口失焦被当成「指针离开文档」（`window.addEventListener("blur", onPointerGone)`），
而**打字不会重算悬停判定**（只有 `pointermove` 会）—— 状态一直粘在「指针不在卡片上」那一档，
直到下一次鼠标移动。复现（无头 Chromium + 真鼠标真键盘，指针全程不动）：

| 步骤 | 改前 | 改后 |
| --- | --- | --- |
| 真鼠标移到输入框上 | `.62` / `blur 4px` | `.62` / `blur 4px` |
| 窗口失焦（鼠标没动） | **`.30` / `blur 0`** | `.62` / `blur 4px` |
| 真点击回页面（坐标不变） | `.30` / `blur 0` | `.62` / `blur 4px` |
| 打字 a、b、中文提交（鼠标不动） | **全程 `.30` / `blur 0`** | 全程 `.62` / `blur 4px` |
| 真鼠标动 1px | `.62` / `blur 4px` | `.62` / `blur 4px` |

改法（`lib/client.js` 一处）：失焦改走独立处理器 —— **只丢命中缓存并按最后的坐标重算**，
坐标不清（坐标是几何事实，不随窗口焦点改变）；「真离开」只由 `documentElement` 上的
`pointerleave` 判定。相邻状态复验：真离开仍回常态（`.30` / `blur 0`）、失焦与真离开叠加时
真离开赢、输入法 composition 与提交不改判定、卡片节点被整体替换后仍判定悬停。

守卫：`tools/check.mjs` 第 13 项（契约 `glass.pointer` 的 `must` / `forbidden`、失焦处理器体内
只许「丢缓存 + 重算」、悬停底色只有一处定义）+ 真机断言 `tools/probes/contract.js` 第 ⑫ 段。

## 10. 进行中指示：两种暗带移除 + 闪烁橙点 + 文字水波（2026-09-25）

用户报「与背景不协调的黑色横带」并要求彻底移除，改成「工具调用等条目前面一颗闪烁的橙点」；
追加要求：「把扫光关掉，换成让字体像在水波中规律抖动（频率和扫光一致）」。

机器可读的那一半在 `contract/ui-contract.json` 的 `busy` 段（`dot` / `wave` / `sweep` /
`seatBackground` / `knownExceptions` / `measured`），静态由 `tools/check.mjs` 第 14 项守，
真机由 `tools/probes/contract.js` 第 ⑬ 段守。这一节只讲**为什么是这样做**：

- **锚点只用属性，不用哈希类名**：`[data-state="running"]` 是 DSH 自己给「运行中」条目的标记
  （全部赋值点已穷举：工具 / bash / 命令卡 / 推理 / cordis / skill / present；另有一个
  open-in-app 用的是 `busy`/`idle`，不会误命中）。DSH 自己是三个包各写一条扫光规则 ——
  我们一条选择器覆盖整族，新出现同族条目不用加代码。
- **关扫光用 `content: none` 而不是 `animation: none`**：只停动画会留下一块静止的 300px 中性黑，
  比扫过去更难看。爆炸半径也穷举过：全前端「选择器里带 `_row`/`_root` 的 `:after` 规则」
  只有这五族扫光 + 其中三族的 reduced-motion 兜底（共 8 条），所以打不到别的东西。
  顺带补上一个缺口：**tool 族原本没有 reduced-motion 兜底**，现在扫光整个不存在了。
- **点走绝对定位、水波只走 `transform`**：两者都不参与排版 ⇒ 状态切换零位移（实测：行与内层盒
  在 非运行→运行→非运行 中逐值相同）。文字水波振幅只有 ±1px、周期 2.6s（与原扫光同频），
  比"整行抖动"克制得多。
- **颜色一处定义、且必须挂在 `body` 作用域**：DSH 的语义 token 只定义在 `body` 上；
  写进 `:root` 时 `var()` 链会在计算值阶段失效 ⇒ 自定义属性变成保证无效值 ⇒
  整条 `background` 作废 ⇒ **点画得出来但是透明的**（尺寸圆角都对）。这是实测踩到的，
  第 14 项专门拦它。
- **尊重系统「减少动态效果」**：动画停、点变成静态橙点（`opacity 1`）、文字静止 ——
  「进行中」照样看得见（行内摘要仍写着在做什么）。
- **bash 样例行那条死裁剪必须放开**：`CY-8Ka_root` 的 `data-state` 与 `overflow:hidden` 在同一个
  元素上 —— 它原来裁的就是那条扫光（300px、从 `left:-300px` 扫进来）。扫光整条关掉后这层裁剪
  再没有存在理由，却会把行首的点一起裁掉。真机实测（跑 bash 的 `sleep`）**这一行就是顶层条目**，
  `data-state="running"` 的元素只有它一个，所以不能只登记成例外：放开 `overflow: visible`
  （不碰 padding / 间隙 / 尺寸 ⇒ 零位移；对其他族无操作，实测它们的 root 本来就是 visible）。
  放开之后像素复核：三条克隆行的行首各一颗 8×8 橙点。
- **范围边界（如实登记）**：流式正文 / 重试行 `[data-active]` / 等待确认不带 `data-state`，
  不在这一族里（想扩要单独走一轮）。
